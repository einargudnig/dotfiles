einargudnig/dotfiles

One repo, one command,
a working machine.

A macOS and Linux environment managed with GNU Stow. Seventeen packages of configuration, 153 Homebrew formulae, and six language managers — reproduced on a bare box by a single curl.

The model

Every top-level directory is a stow package whose internal layout mirrors the path of its files relative to $HOME. Stow reads that shape and links it in:

zsh/.zshrc→~/.zshrc
nvim/.config/nvim/→~/.config/nvim
claude/.claude/skills/→~/.claude/skills
scripts/.local/bin/papercut→~/.local/bin/papercut
lazygit/Library/Application Support/…→~/Library/Application Support/lazygit

They are symlinks, not copies. Editing ~/.zshrc is editing the repo — there is no sync step, and nothing to forget. That property is the whole reason stow beats a copy-based manager here: agents and installers that write into ~/.claude land in version control for free.

Bare machine

$ curl -fsSL https://raw.githubusercontent.com/einargudnig/dotfiles/master/bootstrap.sh | bash

Xcode command line tools → Homebrew → clone → every recorded package → link. Idempotent, so re-running it repairs a machine that has drifted rather than starting over.

Homebrew is split in two on purpose. It runs on Linux, but casks and Mac App Store apps do not exist there — and a single Brewfile containing cask lines hard-fails brew bundle on Linux.

Versions are stripped from the npm and bun manifests. Pinning them makes a fresh machine fail on a yanked release. These lists exist to say have this tool, not to reproduce an exact build.

Sharp edges

Things that cost real debugging, recorded so they only cost it once.

Ignore files replace, not extend

Creating a .stow-local-ignore discards stow's built-in ignore list entirely. Restate the defaults or .git starts getting linked.

Stow links disk, not git

Gitignored runtime state is still on disk and still gets linked. Without an ignore file, ~/cache and ~/history.jsonl appear in your home directory.

restow blinks the shell config

stow -R unlinks before it relinks, so ~/.zshenv is briefly gone. A shell starting in that window has no PATH. Use absolute paths in anything scripted around it.

gitignore paths are anchored

Moving a tree breaks every ignore pattern that named its old path. One restructure made 110,000 vendored files newly visible to git.

Relative links shift with depth

97 skill symlinks pointed at ../../../.agents. Moving the tree one level down invalidated all of them at once.

bash 3.2 is the floor

The bootstrap runs before Homebrew exists, so /usr/bin/env bash is macOS's bash 3.2. No mapfile, no associative arrays.
